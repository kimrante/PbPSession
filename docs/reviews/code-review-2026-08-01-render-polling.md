# 코드 리뷰 보고서 — 렌더링 · 서버 폴링 (2026-08-01, v0.9.1)

main 최신(`fb128eb`) 기준으로 **렌더링 문제(캡처·루비·화면)와 서버 폴링/트래픽**을 집중 점검한 결과.
v0.5.3 이후 15개 커밋(대화 캡처 v0.7.x, 타이핑 인디케이터 v0.9.0, 헤드업 알림, UI 감사, 요청 9건 등)이 대상.
**다른 세션에서 이 문서만 보고 수정 작업을 진행할 수 있도록** 항목마다 위치·재현·수정 방향을 명시한다.
기준 커밋: `fb128eb`. 라인 번호는 이 커밋 기준.

## 총평

- **폴링/트래픽: 건강함.** 기존 계약 전부 유지(폴 주기·영구 캐시·백오프·방별 FCM), 최근 15개 커밋에서
  **새 리스너·폴링 0건**(리스너 전수 인벤토리로 확인), 타이핑 인디케이터는 기존 members 리스너에 편승했고
  비용은 허용 범위(격렬한 3시간 세션 ≈ 무료 쿼터의 ~10%). functions 무변경. v0.8.0은 오히려 트래픽 순감소.
- **단, 이전 저장·폴링 지시서(PR #15)의 M1·M2가 미반영 상태** — 해당 문서에만 조치 결과 헤더가 없고 코드도
  그대로다. 특히 M1은 메시지 영구 누락 가능성이라 **이번 목록의 최우선**으로 재수록한다(P0).
- **렌더링: 캡처 기능에 심각 2건.** 페이지 하단 무통보 클리핑(추정치 과소+클램프)과 장범위 캡처 OOM.
  루비 베이스라인 앵커 재작성은 양 플랫폼·캡처·HTML 전부 정합 확인(잘 됨). 화면 렌더링에서는 데스크톱
  시간 접기가 또 부분 사문화된 것(이전 R2 수정이 GM 분기만 커버) 등 데스크톱 미이식 2건.

권장 수정 순서: **P0 → R1 → R2 → R3·R4 → S1 → 나머지**.

## P — 폴링/트래픽

### P0. [이월, 최우선] 이전 지시서 M1·M2 미반영 — 재확인 결과 코드 그대로

`docs/reviews/code-review-2026-07-30-storage-polling.md`의 M1·M2가 반영되지 않았다(문서에 조치 결과 헤더
없음, 코드 확인 완료). 요지 재수록:

- **M1 — 폴링 윈도가 다음 간격 기준**: `desktop/.../Main.kt:298` `windowMs = interval * 2` —
  미포커스 30초→활성 2.5초 전환 첫 폴의 윈도가 5초뿐이라 직전 ~30초 공백의 시계 오차·늦은 커밋 메시지가
  **영구 누락**될 수 있다. 수정 ~2줄: `prevInterval` 추적 후 `windowMs = maxOf(interval, prevInterval) * 2`.
- **M2 — 로그 초기화 부활 레이스**: `Main.kt:446-465`가 IO 스레드에서 `messages`를 직접 비우고, 폴 병합
  (`:302-322`)은 `fresh`만 `deletedDocIds`로 거른다 — 진행 중이던 폴이 리셋 전 목록을 복원하고 파일
  캐시에 재영속화. 수정: 리셋의 로컬 상태 변경을 UI 스코프로 홉 + 병합 시 기존 `messages`도
  `deletedDocIds` 필터(자가 치유). 전체 read 후 문서별 DELETE인 비용 비대칭도 함께 정리 권장.
- (같은 문서의 L1~L5도 미반영 — M 처리 시 함께 훑을 것.)

### P1. [권장] 타이핑 스로틀 4초 → 6초, TTL 7초 → 9초 (3줄, 쓰기 33% 절감)

### P2. [낮음] 타이핑 표시의 시계 오차 취약 — 수신 시 clamp 1줄

## R — 렌더링: 대화 캡처

### R1. [높음] 페이지 하단 무통보 클리핑 — 추정치 과소 + 측정 후 클램프 (양 플랫폼)

- **위치**: `app/src/main/java/com/pbp/app/export/CaptureRenderer.kt:225`(`height.coerceAtMost(MAX_HEIGHT_PX)`
  — 측정 후 잘라내고 그대로 draw), `:156-160`(`estimate()` — **GM 메시지가 길이 무관 90dp 고정**, 일반
  텍스트도 실측 대비 25~35% 과소), `:128-144`(추정 기반 분할, 예산 4,000dp). 데스크톱 동일:
  `desktop/.../export/CaptureRenderer.kt:98-101`(프로브 씬이 8,000px라 그 이상은 측정 자체가 불가).
- **재현**: 긴 GM 서술 1건(2,000자 ≈ 실측 ~1,700dp인데 추정 90dp) 포함 범위를 캡처 → 청크 실측이
  8,000px 초과 → 페이지 하단(마지막 메시지 일부 + 낙관 푸터)이 **에러 없이 잘려 나감**.
- **수정 방향**: 클램프 제거 — 측정 결과가 `MAX_HEIGHT_PX` 초과면 청크를 메시지 단위로 이분해 재렌더
  (측정 기반 재분할 루프). 최소한 `estimate()`의 GM 분기를 본문 길이에 비례시키고 일반 텍스트 계수를
  실측(240dp 말풍선 ≈ 한글 17~18자/줄)에 맞출 것. 양 플랫폼 동일 수정.

### R2. [높음] 장범위 캡처의 총 비트맵 메모리 무제한 → OOM

- **위치**: 페이지당 720×8,000×4B = **23MB**. 선택은 200건 제한이지만 **높이 제한이 없어** 긴 메시지
  200건 ≈ 20페이지 ≈ **460MB**가 `CaptureHolder.pages`에 동시 보유 + 프리뷰가 전부 디코드
  (`CapturePreviewScreen.kt:201-210`). Android 힙(192~512MB)에서 OOM, 페이지 N에서 실패하면 N-1개도 소실.
- **수정 방향**: `estimateHeightPx` 기반 상한 추가(200건 제한과 같은 방식으로 거부 안내), 또는 렌더
  즉시 PNG로 캐시 디렉터리에 압축 저장하고 프리뷰는 파일에서 로드(메모리 상주 1~2페이지로 제한).

### R3. [중간] 아바타/배경 프리로드가 별도 ImageLoader로 들어감 — 사실상 무효

- **위치**: `app/.../export/CaptureRenderer.kt:168` — `ImageLoader(context)` 신규 생성. 실제 렌더의
  `AsyncImage`/`Avatar`는 **싱글턴 로더**(`PbpApp` — `SingletonImageLoader.Factory`, `allowHardware(false)`)
  를 쓰므로 프리로드 캐시가 공유되지 않고, 새 로더는 기본 `allowHardware(true)`이기까지 하다. 렌더 루프는
  이미지 로드 완료를 기다리지 않으므로(`:215-223`), 싱글턴 메모리 캐시에 없는 아바타(스크롤로 밀려난
  옛 메시지)는 **빈 원으로 찍힌다** — 프리로드가 막으려던 바로 그 증상.
- **수정**: `coil3.SingletonImageLoader.get(context)` 사용(캡처마다 새 로더 누수도 함께 제거).

### R4. [중간] 공유 중 재렌더 → recycled bitmap (조용한 부분/빈 공유, 1프레임 크래시 가능)

- **위치**: `CapturePreviewScreen.kt:247-260` — 공유 버튼이 `busy`를 세우지 않아 토글이 활성 상태.
  공유 압축(IO) 중 배경/잡담 토글 → `rerender()` → `CaptureHolder.set()`의 `clear()`가 기존 페이지를
  `recycle()`(`CaptureHolder.kt:41`) → `bitmap.compress`가 recycled 비트맵에서 실패(파일별 runCatching이
  삼켜 부분/빈 공유), 화면의 `Image` 노드도 한 프레임 크래시 가능.
- **수정**: 공유 코루틴 동안 `busy = true`. 근본적으로는 `set()`에서 즉시 recycle하지 않기(교체 후 GC 위임).

### R5. [중간, 데스크톱] 청크 렌더 실패가 무통보 누락 페이지로

- **위치**: `desktop/.../export/CaptureRenderer.kt:70-77` — `mapIndexedNotNull { runCatching { ... }.getOrNull() }`.
  중간 청크 실패 시 그 페이지만 사라지고 "1/3", "3/3" 라벨의 캡처가 저장됨. 모바일은 v0.7.2에서 정확히
  이 패턴을 제거했는데 데스크톱은 남음.
- **수정**: 예외 전파 + UI 표시(모바일과 동일 정책).

### R6. [중간, 데스크톱] 미표시 메시지의 아바타가 빈 원 — P3와 동일 수정
