03 · 규칙 — 누가 무엇을 누를 수 있나

선행 조건 — GM 기기에는 상대 캐릭터가 없다

캐릭터 프로필은 기기 로컬 데이터이고 서버로 동기화되지 않습니다 (profiles 테이블에 sync 경로가 없음). 그래서 이 기능은 캐릭터 명단 공유가 먼저 필요합니다. 방법은 이미 있는 rooms/{id}/members/{uid} 문서에 이름·이모지·이름색·숫자 값의 이름 목록만 얹는 것입니다 — 그 문서를 보는 리스너가 이미 하나 돌고 있어(읽음·입력 중 표시) 추가 읽기가 0입니다. 값(숫자)은 보내지 않습니다 — GM에게 필요 없고, 굴림은 대상자 기기에서 그때의 값으로 하기 때문입니다.

버튼은 GM 프로필일 때만

활성 프로필이 isGm = true일 때만 판정 요청 줄이 보입니다. 프로필을 바꾸면 즉시 사라집니다 — 방의 마스터 여부(room.isMaster)가 아니라 지금 말하고 있는 프로필을 기준으로 합니다. GM이 자기 NPC로 말하는 중에는 요청을 걸 수 없다는 뜻이고, 그게 자연스럽습니다.

대상 목록은 플레이어 캐릭터만

GM 프로필은 제외합니다 — GM은 입력창에서 직접 굴릴 수 있으니 자기에게 요청할 일이 없습니다. 오너 프로필은 애초에 CharacterProfile이 아니라 이 목록에 들어오지 않으므로 별도 필터가 필요 없습니다. 결과적으로 규칙은 profiles.filter { !it.isGm } 한 줄입니다.

숫자 값만 판정할 수 있다

이미 채팅 팔레트가 같은 규칙을 씁니다(ProfileStats.paletteSuggestions는 toIntOrNull() != null인 값만 후보로 삼음). 판정 요청도 같은 규칙을 그대로 씁니다 — 직업 '탐정' 같은 글자 값은 목록에 나오지 않습니다. 숫자 값이 하나도 없는 캐릭터는 선택 자체가 막힙니다(위 B컷의 등대지기).

누를 수 있는 사람은 '그 캐릭터를 가진 기기'

캐릭터 프로필은 각 기기의 로컬 데이터이고 서버로 동기화되지 않습니다. 그래서 대상 판정은 이름으로 합니다 — 내 profiles에 같은 이름의 캐릭터가 있으면 내가 굴릴 수 있습니다. 같은 이름의 캐릭터가 양쪽에 있으면 둘 다 누를 수 있게 되는데, 1:1 방에서 같은 이름을 쓰는 경우가 드물고 막으면 오히려 정상 사용을 깨므로 이름 일치로 둡니다.

두 번 굴러가지 않게

굴림은 요청 1건당 한 번입니다. 굴린 뒤에는 완료 상태로 바뀌어 다시 눌리지 않습니다. 연타·양쪽 동시 탭 대비로 보내기 전에 로컬 상태를 먼저 잠그고, 이미 결과가 달린 요청은 다시 처리하지 않습니다. 굴린 사실은 요청 메시지에 남깁니다(아래 표 참조).

굴림은 지정된 캐릭터로 나간다

탭한 사람의 활성 프로필과 무관하게 요청에 적힌 캐릭터의 값으로 굴립니다. "카야, 민첩 판정"인데 밤샘꾼으로 굴러가면 안 됩니다. 프로필을 자동으로 바꾸지도 않습니다 — 굴림 한 번만 그 캐릭터 이름으로 나갑니다.

04 · 구현 지시 — 무엇을 어디에

기존 다이스 굴림 경로(DiceBot · 다이스 카드)는 그대로 쓰고, 그 앞에 '요청' 한 단계만 붙입니다

대상지금변경
캐릭터 명단 공유
(선행)		 프로필은 기기 로컬 — SELECT * FROM profiles WHERE roomId IS NULL OR roomId = :roomId. 서버로 나가는 경로가 없음 각 기기가 자기 rooms/{id}/members/{uid} 문서에 characters 배열을 merge로 얹습니다 — [{name, emoji, nameColor, stats:["민첩",…]}]. 값(숫자)은 넣지 않습니다. 이미 observePeerState가 같은 컬렉션을 구독하고 있어 추가 읽기 0이고, 프로필이 바뀔 때만 씁니다
메시지 타입 enum MessageType { TEXT, DICE, SYSTEM } JUDGE 추가. 구버전 클라이언트와 호환됩니다 — SyncMapping.fromMap이 runCatching { valueOf }.getOrDefault(TEXT)라 모르는 타입은 평범한 텍스트 말풍선으로 보입니다(크래시 없음). 데스크톱도 문자열 비교라 else로 떨어집니다
요청이 담는 값 diceExpr · diceOutcome 필드가 이미 있음 body = "카야, 민첩 판정"(구버전에서 보일 문구이기도 함), diceExpr = Rules.judgeCommand(rule, "민첩"). 대상 이름은 신규 컬럼 judgeTarget, 굴림 완료 표시는 judgeRolledAt. Room은 version = 10에 명시 마이그레이션을 쓰므로 MIGRATION_10_11에 ALTER TABLE messages ADD COLUMN 2개. SyncMapping의 toMap/fromMap에도 추가(가산 변경이라 구버전은 무시)
GM 전용 버튼 InputZone: 프로필 스트립 → (판정 팔레트) → 입력줄 스트립과 입력줄 사이에 한 줄 추가. 조건은 profiles.find { it.id == activeId }?.isGm == true. 규격은 판정 팔레트 칩과 같은 캡슐(r-pill · 세로 6dp · 가로 12dp)을 써서 같은 자리에 같은 모양이 오게 합니다
선택 시트 없음 신규 ui/chat/JudgeRequestSheet.kt — 2단계(프로필 → 값)를 한 ModalBottomSheet 안에서 전환. 상태는 ChatScreen에 rememberSaveable로 judgeTargetId: Long? · judgeStat: String?. 값 목록은 ProfileStats.decode(profile.stats)를 toIntOrNull() != null로 거른 것
요청 보내기 PbpRepository.sendMessage가 텍스트+다이스 2건을 넣음 신규 sendJudgeRequest(roomId, target, statName) — JUDGE 메시지 1건만 넣고 pushIfSynced. 여기서는 굴리지 않습니다(굴림은 대상자 기기에서)
판정 문구 렌더 MessageBlock의 when에 SYSTEM·OOC·DICE·GM 분기 message.type == JUDGE 분기 추가. 상태 판정은 rolledAt != null → 완료, profiles.any { it.name == judgeTarget } → 내 차례, 그 밖 대기. 내 차례일 때만 clickable을 붙입니다(대기 상태에 리플이 생기지 않도록)
탭 → 굴림 DiceBot.parse/roll + Rules.judgeOutcome 신규 rollJudge(message) — ① 이미 judgeRolledAt != null이면 즉시 반환(중복 방지) ② 대상 이름의 프로필을 찾아 ProfileStats.substitute로 {민첩}을 값으로 치환 ③ DiceBot.roll → 기존과 똑같은 DICE 메시지 생성(diceExpr = "카야 · 1d100<=55") ④ 요청 메시지의 judgeRolledAt을 채워 로컬 갱신 + 전파. ②의 프로필은 활성 프로필이 아니라 이름으로 찾은 그 프로필
HTML 로그 :shared LogExport가 타입별로 렌더 JUDGE 분기 추가 — 종이 톤 로그에서는 버튼이 의미 없으므로 "카야, 민첩 판정" 한 줄로만. 굴림 결과는 어차피 뒤의 다이스 카드로 남습니다
데스크톱 ChatPane · InputZone이 모바일과 같은 구조 같은 규칙을 이식. 시트는 데스크톱의 기존 오버레이 방식(OverlayScaffold)을 쓰고, Message가 type: String이므로 "JUDGE" 비교. 대상 판정은 AppConfig.profiles의 이름 일치
