# PbP — 1:1 TRPG 채팅 앱 설계안

디스코드의 문법을 빌린 1:1 플레이-바이-포스트(Play-by-Post) 안드로이드 앱.
캐릭터 프로필을 갈아입으며 대화하고, 방마다 하나뿐인 GM과 다이스봇이 세션을 진행한다.

- UI 목업: [ui-mockup.html](ui-mockup.html) (아티팩트: https://claude.ai/code/artifact/2d4fa924-e388-406b-9c22-7d5e07f9ca7c)
- 통신 방식: **2인 실시간 통신** (확정, 2026-07-27) — 동기화는 3단계에서 Firebase로 구현

## 요구사항

1. 디스코드를 닮은 외형의 1:1 채팅 앱
2. 캐릭터 이름·프로필 이미지를 여러 개 등록하고 교체 가능
3. 현재 선택된 프로필의 이름·이미지로 메시지 발신
4. GM 역할의 특수 프로필이 **방마다 정확히 1개** 존재
5. 채팅방 다수 생성 가능
6. 다이스봇: `1d6` → 6면체 굴림 결과를 정수로 출력. 지원: d6, d10, d100 (추후 추가 가능)
7. 대화를 HTML 형식 로그로 다운로드

## 기술 스택

| 영역 | 선택 | 비고 |
|---|---|---|
| 언어/UI | Kotlin + Jetpack Compose (Material 3) | 다크 테마 기본 |
| 아키텍처 | MVVM + 단방향 데이터 흐름 | Compose ← ViewModel ← Repository |
| 로컬 DB | Room | 메시지·캐릭터·방 저장, 오프라인 열람 |
| 동기화 (3단계) | Firebase Firestore + Auth + Storage | 1:1 소규모에 운영 부담 최소 |
| 이미지 로딩 | Coil | |

## 데이터 모델

- **ChatRoom** — 방 이름, 아이콘, 참여자, 생성일, 사용자별 "현재 발화 프로필". 무제한 생성.
- **CharacterProfile** — 이름, 프로필 이미지, 한 줄 소개, 소유자. 계정 전역 자산으로 방 간 재사용.
- **GM 프로필** — `isGM = true`인 특수 프로필. 방 생성 시 자동으로 1개 생성되어 그 방에만 귀속.
  삭제 불가, 이름/이미지만 편집 가능. "방마다 정확히 1개"를 생성 규칙으로 보장.
- **Message** — 본문, 타입(`TEXT`/`DICE`/`SYSTEM`), 시각, **발신 시점의 프로필 이름·이미지 스냅샷**.

### 스냅샷 원칙

메시지가 프로필을 참조하면 캐릭터 수정 시 과거 로그의 얼굴까지 바뀐다.
발신 순간의 이름·이미지를 메시지에 복사해 "그때 그 인물"을 로그에 영구 보존한다.
HTML 내보내기도 이 스냅샷만으로 완결된다.

### 방별 활성 프로필

"지금 누구로 말하는가"는 방마다 따로 기억한다. A방에서는 리안, B방에서는 카야 —
방을 오가도 배역이 섞이지 않는다.

## 화면 구성

1. **홈** — 좌측 레일(원형 방 아이콘) + 방 목록. 마지막 메시지 미리보기는 캐릭터명으로 표시.
2. **채팅방** — GM은 금테 아바타 + `GM` 배지, 다이스봇은 `BOT` 배지. 프로필 전환은 중앙 시스템 라인으로 기록.
3. **프로필 전환 바텀시트** — 입력창의 프로필 칩 탭 → 선택 → 다음 메시지부터 새 인물로 발화. GM 최상단 고정.
4. **캐릭터 관리** — 등록/편집/삭제. 삭제 시 사용 중인 방 표시.
5. **로그 내보내기** — 기간·이미지 포함 여부 선택 후 단일 HTML 저장.

## 다이스봇

- 문법: `/r XdY` (예: `/r 1d6`, `/r 2d6`, `/r 1d100`)
- 메시지 전송 시 정규식으로 감지 → 다이스봇 프로필의 `DICE` 메시지로 자동 답장
- 지원 면 수는 설정 목록 `[6, 10, 100]`으로 관리 — d4, d20 추가는 숫자 하나 추가로 끝
- 여러 개 굴림은 내역 표시: `2d6 → 3 + 5 = 8`
- 주사위는 발신자 기기에서 굴려 메시지로 기록. 조작 방지가 필요해지면 Cloud Functions 서버 굴림으로 전환 가능

## HTML 로그 내보내기

- 방 전체(또는 기간)를 **단일 HTML 파일**로: CSS 인라인, 아바타 base64 내장
- 앱은 다크, 로그는 읽기용 라이트 테마 (리플레이 감상·인쇄용)
- 저장은 SAF 문서 선택기, 공유 시트 지원

## 개발 단계

1. **MVP (로컬)** — 방/캐릭터 CRUD, GM 자동 생성, 프로필 전환, 채팅 UI, 다이스봇. 서버 없이 완결. ← 완료 (2026-07-27, 에뮬레이터 검증)
2. **HTML 내보내기** ← 완료 (2026-07-28, 에뮬레이터에서 SAF 저장까지 검증)
3. **2인 동기화** — Firestore 연동, 초대 코드로 방 참여 ← 완료 (2026-07-28, Firestore 로컬 에뮬레이터로 양방향 E2E 검증)

## 2인 동기화 구조 (3단계)

- Firestore 구조: `rooms/{id}` (name, icon, createdAt, inviteCode) + `rooms/{id}/messages/{id}` (스냅샷 필드 + authorUid)
- 로컬 Room DB가 화면의 소스, Firestore는 전송 채널. 발신 = 로컬 삽입 후 push, 수신 = 스냅샷 리스너 → 로컬 삽입
- 중복 방지: 메시지 `remoteId` + `authorUid`(기기별 UUID, 계정 불필요) + pending-write 필터
- 초대: 방 공유 시 6자리 코드 발급(`rooms.inviteCode`), 상대는 홈 → 참여에서 코드 입력
- 프로필 이미지는 기기 로컬 경로라 동기화하지 않음(이모지·이름만 전달). 이미지 동기화는 Firebase Storage 필요 → 추후
- 주사위는 발신 기기에서 굴림(신뢰 모델: 2인 협력 플레이 전제)

### 실서비스 전환 방법

현재 `app/src/main/res/values/firebase.xml`의 `firebase_project_id`가 `demo-pbp`라서
로컬 Firestore 에뮬레이터(10.0.2.2:8080)에 붙는다. 실서비스로 바꾸려면:

1. Firebase 콘솔에서 프로젝트 생성 → Android 앱 등록 (패키지 `com.pbp.app`)
2. Firestore Database 생성
3. `firebase.xml`의 세 값을 프로젝트 설정의 실제 값(project_id, App ID, Web API Key)으로 교체
4. 보안 규칙 설정 필요 — 현재 클라이언트는 인증 없이 동작하므로 규칙을 열어두거나(비공개 코드 기반),
   추후 Firebase 익명 인증 + 규칙 강화 권장

로컬 개발 검증: `npx firebase-tools emulators:start --only firestore --project demo-pbp` 후 앱 실행.
