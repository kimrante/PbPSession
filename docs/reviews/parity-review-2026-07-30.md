# 10-루프 리뷰 2026-07-30 — 파리티·스크롤·리소스·코드 클린

요청: ① DESKTOP↔APP 기능 차이를 발견하는 즉시 APP 기준으로 통일, ② 최신 메시지
송수신 시 스크롤 이슈 수정, ③ 리소스 전달 깨짐 점검·수정, ④ 코드 클린.
아래 모든 수정은 코드에 반영·푸시됨.

## 루프 1 — 스크롤 버그 (핵심 수정)

**원인**: 여러 건이 한 배치로 도착하면(상대 판정의 TEXT+DICE 쌍, 잠시 자리를
비운 뒤 몰아 수신) LazyColumn이 보고 있던 항목에 앵커되어
`firstVisibleItemIndex`가 도착 수만큼 커진다. 기존 "바닥 근처(≤1)" 판정이
2건 이상 배치에서 항상 실패 → 스크롤이 따라가지 않음.

**수정(양쪽 동일 규칙)**: 직전 최신 메시지의 현재 위치를 찾아 "이번에 몇 건
추가됐는지"를 계산하고, 근접 판정을 도착 수만큼 보정. 데스크톱은 추가로 내
전송 스크롤을 앱과 같은 방식(전송 시점 플래그를 세워 실제 도착까지 유지, N4)으로
통일. '이전 대화 불러오기'(위쪽 로드)는 최신 ID가 그대로라 영향 없음.

## 루프 2 — 파리티 전수 대조 (차이 목록 확정)

앱에 있고 데스크톱에 없던 것: 메시지 편집/삭제, 프로필 편집·삭제, 캐릭터 값
편집 UI, 클립보드 캐릭터 가져오기, 방 로그 리셋, 방 나가기 → 루프 3–6에서 이식.
보류 항목은 하단 "질문/보류" 참조.

## 루프 3 — 데스크톱 메시지 편집/삭제 (이식)

- 내 메시지(말풍선·서술·잡담) 길게 누르기 → 편집/삭제 팝업 → 편집 오버레이·삭제 확인
- REST `updateMessage`(body+editedAt PATCH) / `deleteMessage`(DELETE) 추가
- 폴링과의 상호작용 보정 2건:
  - 삭제 직후 30초 재수신 윈도가 지운 메시지를 '신규'로 되살리는 것 방지(삭제 ID 억제 목록)
  - 편집 감지(C10)를 "더 새로운 editedAt만 수용"으로 — 내 편집을 윈도의 구버전이 되돌리지 않게
- 30초 밖 편집·삭제의 상대 실시간 반영 한계(S7)는 기존 문서화된 수용사항 그대로

## 루프 4 — 데스크톱 프로필 편집·삭제 + 값(stats) 편집 UI (이식)

- 프로필 칩 길게 누르기 → 편집 오버레이(이름/이모지/이름색/말풍선색/값 목록)
- 캐릭터 값 편집 UI — 이제 config.json 수동 편집 불필요, 판정 팔레트와 즉시 연동
- 프로필 삭제: 전역 목록 인덱스를 참조하는 각 방의 활성 인덱스를 재매핑
  (뒤 인덱스는 -1, 삭제된 활성은 첫 비GM으로). GM·마지막 프로필은 삭제 불가

## 루프 5 — 데스크톱 클립보드 캐릭터 가져오기 (이식)

- CharacterCodec(ccfolia JSON → 이름+값)을 데스크톱 Logic.kt에 동일 규칙으로 이식
- 프로필 오버레이의 "클립보드 캐릭터 코드 불러오기" 버튼 — 이름·값 자동 채움

## 루프 6 — 데스크톱 방 로그 리셋 + 방 나가기 (이식)

- 방 설정 하단 "방 로그 초기화": 서버 문서를 먼저 전부 삭제, 성공 시에만 로컬
  비움(모바일 N2와 동일 순서) + "방 로그가 초기화되었습니다" SYSTEM 흔적 전송.
  상대 기기는 REMOVED 리스너로 함께 지워진다
- 방 카드 길게 누르기 → 나가기 확인 → 목록 제거 + 서버 멤버 문서 정리
  (레거시 deviceId 문서를 먼저 지우는 R5 순서 포함 — 유령 푸시 방지)

## 루프 7 — 리소스 전달 경로

- **수정**: 모바일 `resolveAvatar`가 파일을 직접 쓰다 중단되면 깨진 아바타가
  영구 캐시됨(exists()만 확인) → 임시 파일 + 원자적 교체
- 점검 후 이상 없음: 아바타 업로드 축소(≤256px, 알파는 PNG)·해시 dedup·1MB 문서
  한도 여유, 수신 실패 시 재시도(캐시 안 함), 데스크톱 디코딩 폴백(이모지),
  REST UTF-8 인코딩, 값 이름의 제어문자·중괄호 sanitize, 폰트 번들
- 기록만(수용): 모바일 수신 아바타 파일이 filesDir에 누적(항목 수가 적어 무해)

## 후속 이식 (사용자 결정 반영, 같은 날)

1. **방 목록 미리보기·미확인 배지**: 보류 확정 (read 과금 상충)
2. **HTML 로그 내보내기 이식 완료**: 데스크톱 export/LogExporter.kt — 모바일과
   동일 형식(종이 톤, 서술 문단, 인용 분리, 잡담 〔잡담〕, 마크다운/루비, 판정
   등급 색). 상단 바 "내보내기" → OS 저장 대화상자. 아바타는 avatarId → 방
   avatars 문서에서 받아 데이터 URI로 내장(매직 바이트 검사 P3-9 동일)
3. **프로필 이미지 업로드 이식 완료**: 프로필 편집의 "프로필 이미지 선택" →
   로컬 512px 축소 저장 → 전송 시 256px 축소본(알파는 PNG, 모바일과 동일 정책)을
   방 avatars/{md5} 문서로 업로드하고 메시지 avatarId로 연결. 칩·미리보기에도 표시
4. **데스크톱 OS 알림 완료**: 트레이 알림(DesktopNotifier) — 창이 포커스를 잃었을
   때 새 수신(대화만, SYSTEM 제외)에 "~님의 메시지가 도착했습니다." 표시. 본문
   비노출 규칙 동일. 폴링이 선택된 방만 도는 구조라 **다른 방의 알림은 불가**
   (미리보기 보류와 같은 이유 — read 절약)
